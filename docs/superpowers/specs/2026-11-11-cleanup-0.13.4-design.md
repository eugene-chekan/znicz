## 1. Closing a drawer or modal on Stage blinks

Since #70, closing an overlay on Stage runs `terminal.clear()` and sets
`cover_draw_key = None`. The clear blanks the screen at once; the next frame
first asks the player for its state, then resizes and re-encodes the cover
(about 35–55 ms in release on a fast machine, Sixel slowest) before anything
is drawn again. That gap is the visible blink.

Measured: re-rendering an already encoded Sixel or Kitty protocol costs
under 0.1 ms. ratatui-image keeps Sixel (and iTerm2) data in the image's
first cell, so a cleared buffer re-sends it without encoding. Kitty transmits
the image once (`transmitted` flag) and only places it afterwards.

**Behaviour:**

- An overlay closing on Stage marks a repaint as pending. The next frame
  does the clear and the draw together inside a synchronized update
  (`crossterm::terminal::BeginSynchronizedUpdate` / `EndSynchronizedUpdate`,
  DEC mode 2026). Terminals that support it show the old frame until the new
  one is complete; others ignore the sequences and still get the clear and
  the frame back to back.
- The cover is re-encoded after the clear only for the Kitty protocol
  (`cover_needs_retransmit(Some(ProtocolType::Kitty))`). Sixel, iTerm2 and
  half-blocks keep the encoded image; the cleared buffer re-sends it.
- `needs_full_redraw` is unchanged (same cases).

## 2. Autostarted player becomes a zombie under a long-lived parent

`spawn_detached_player_exe` (`znicz/src/daemon.rs`) drops the `Child`
without waiting. When the player exits while its parent keeps running
(`znicz mcp` under an agent), the kernel keeps a `<defunct>` entry until
the parent exits.

**Behaviour:** after spawning, a named background thread
(`znicz-player-reaper`) owns the `Child` and calls `wait()`. A parent that
exits first simply ends the thread; the player is unaffected (it is
reparented as before).

## 3. Tests leave temporary folders behind (#79)

Replace hand-built `std::env::temp_dir().join(format!("znicz-…"))` paths in
tests with `tempfile::TempDir` / `NamedTempFile` (workspace dev-dependency
`tempfile = "3"`). A test that needs a path that does not exist yet uses
`dir.path().join("name")` and keeps `dir` alive for the whole test. Keep
any existing per-crate helper (e.g. `znicz-library`'s `temp_dir`) but make it
return a `TempDir`.

Production fallbacks: `znicz-tui/src/app.rs` and `znicz-mcp/src/server.rs`
fall back to `temp_dir()` for playlists and stations when the data directory
cannot be resolved. Keep the fallback (the app must still start), but log
`tracing::warn!` once naming the path, so saved playlists in `/tmp` are not
silent. Production uses of `temp_dir()` elsewhere (IPC socket paths, cover
download scratch files) are out of scope.

**Check:** `ls /tmp | grep -c znicz` is the same before and after
`cargo test --workspace`.
